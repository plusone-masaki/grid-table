# セル編集機能仕様書

## 1. 背景と狙い
- これまでの実装は表示と選択のみ対応しており、データの直接編集ができない。
- スプレッドシートの基本操作として「セル編集」を導入し、将来のキーボード操作や入力バリデーション拡張の基盤を構築する。
- 初期フェーズではマウス中心のシンプルな編集 UX を提供し、バリデーションやキーバインドは後続フェーズに委ねる。

## 2. 成功条件
- ダブルクリックでセル編集モードに入ると、セル位置に追従する `textarea` エディタが表示される。
- 編集開始時はセルの既存値が `textarea` に挿入され、フォーカスを獲得する。
- 編集中に別セルをクリックすると、現在の入力内容が確定し、クリックしたセルが選択される。
- 編集中にエディタ外（グリッド領域）をクリックした場合も同様に確定する。
- 編集内容はテーブル表示に即時反映され、再描画・スクロール後も保持される。
- 編集中のセルには `aria-selected="true"` が維持され、範囲選択は編集終了後に再開される。

## 3. スコープ
- 対象：ボディ領域のデータセル編集。
- 非対象：行番号列、ヘッダセル、複数行の同時編集、フォーマット／数式入力。
- バリデーション・キーボードショートカット・Undo/Redo は後続フェーズとする。

## 4. 用語
- **編集ターゲットセル (editingCell)**：現在エディタが開いているセルの絶対座標。
- **編集値 (editingValue)**：`textarea` に入力されたテキスト。確定時にデータセットへ反映する。
- **ローカルデータ (internalData)**：`GridTable` 内で管理する表示用データ。編集結果のソース・オブ・トゥルースとなる。

## 5. UI / 視覚仕様
- エディタは `textarea.grid-table__cell-editor` とし、編集セルの境界に重ね合わせる（絶対配置）。
- スタイル仕様：
  - フォント、行高はセル表示と揃える。
  - 境界線は `2px solid #2563eb`、背景色は白、不透明度 1.0。
  - 影 (`box-shadow: 0 2px 8px rgba(15, 23, 42, 0.12)`) を付与してセルからの浮き上がりを表現。
  - 余白はセル内パディングを踏襲しつつ、`textarea` のスクロールバーが不要な場合は非表示にする。
- エディタは編集セルが表示領域外へスクロールされた場合、自動的に閉じて確定する。
- エディタは単一インスタンスのみ存在し、編集対象以外のセルには表示されない。

## 6. インタラクション仕様
- 編集開始：
  - セルに `onDoubleClick` を設定し、ダブルクリックで `editingCell` と `editingValue` を設定・エディタを表示する。
  - 編集開始時に範囲選択（アンカー/フォーカス）は編集セルに固定される。
- 編集中のクリック挙動：
  - 別セルをクリック → 現在の編集を確定してから新セルの選択処理へ移行。エディタは閉じる。
  - 同一セルをクリック → 編集継続、追加の操作なし。
  - グリッド外クリック → 編集確定の上でエディタを閉じるが、選択状態はアンカーセルに戻す。
- テキスト入力：
  - `textarea` でテキスト入力・改行可。自動リサイズは行わず、セルの高さに合わせる。
- 編集確定：
  - `textarea` の `blur`、または確定トリガー（上記クリック）で `internalData` を更新し、エディタを閉じる。
  - 未変更の場合はデータ更新を行わずに閉じる。
- キーボード操作はこのフェーズでは未実装（Enter/ESC 等のハンドリングなし）。後続で拡張予定。

## 7. 状態管理
- `GridTable` に以下の state を追加する：
  - `internalData: GridDataset` – props から初期化し、編集確定時に更新するローカルコピー。
  - `editingCell: CellCoordinate | null`
  - `editingValue: string`
- 編集開始時に `editingCell` を設定し、`editingValue` に `internalData` の該当値を代入。
- 編集確定時：
  - `internalData` の該当セル値を更新。
  - `selectionRange` / `anchorCell` / `activeCell` を編集セルに固定したままエディタを閉じる。
- `internalData` は `data` prop が変更された場合に再初期化する（依存関係を比較し、参照が変わったときのみ更新）。

## 8. DOM 構造とレイヤー
```
div.grid-table__scroll (relative)
 ├─ ...既存の selection オーバーレイ...
 ├─ textarea.grid-table__cell-editor (absolute, pointer-events: auto) ※編集時のみ
 └─ 既存の grid-table__spacer 群
```
- エディタはスクロールコンテナ直下に配置し、`pointer-events: auto` で入力を受け付ける。
- 位置計算は `editingCell` と列・行メトリクスから算出（選択枠の算出ロジックを再利用）。
- 編集中は `GridTableBody` 側で対象セルのコンテンツを隠さず（重なり表示）。視覚的にはエディタが上書きする。

## 9. アクセシビリティ
- `textarea` に `aria-label` を設定（例：`"Cell editor"`）し、スクリーンリーダーが編集状態を把握できるようにする。
- 編集セルの `aria-selected="true"` は維持する。編集中は `textarea` がフォーカスを受け取る。
- 編集開始時に `textarea` に `focus()` を当て、フォーカス移動を明示する。

## 10. エッジケースと動作要件
- `EMPTY_DATASET_FALLBACK` 利用時も編集可能とし、通常データと同じ条件でエディタを開く。
- セル値が `null` / `undefined` の場合は空文字列として扱う。
- 同一セルを短時間で再度ダブルクリックしても、既存の編集値が `textarea` に保持される（リセットしない）。
- 編集中にデータ props が更新された場合、編集中セルは確定扱いとし、`internalData` を props で再初期化した後に編集結果を反映しない（勝手に上書きしない）。この挙動は将来の要件に合わせて再検討する。
- エディタが表示されたままスクロールで表示外に出た場合は自動確定（`handleScroll` 内で検知）する。

## 11. テスト戦略
- Playwright E2E テスト：
  - ダブルクリックでエディタが表示され、入力後に別セルクリックで値が更新されること。
  - 編集中に他セルへクリックした際、前セルが更新され、新セルが選択状態になること。
  - エディタ表示中にスクロールしてセルが非表示になった場合、自動的にエディタが閉じること。
- エディタ DOM の存在判定（`.grid-table__cell-editor`）と `textarea` の値同期を確認。

## 12. 今後の拡張余地
- Enter/Tab/Escape などのキーボードショートカットによる編集確定・移動。
- `onEditCommit` コールバックの公開と外部データ同期。
- Undo/Redo スタックとの統合。
- セルタイプに応じたバリデーションやフォーマット（数値、日付など）。
